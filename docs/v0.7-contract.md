# 任务管家 v0.7 契约：日志/复盘重做 + 极简今日页 + 回顾合并

> 用户反馈（2026-11-11）：v0.6「只是改了页面」，没看到真正有价值的功能；今日页信息太杂、看不过来；日志总结/复盘被认可但效果不尽人意。
> 结论：v0.7 只做两件事——**把「日志总结/复盘」做成真正有用的内容**（读真实会话内容，而不是状态计数），**把今日页砍到 3 块**。
> 本文件是 v0.7 唯一权威规格。Host 逻辑用 Node 单测验证；浏览器半用静态契约 + /tmp 渲染台截图验证；本会话不重启 Harness（Host 会热加载，最终仍需用户重载一次）。

## 0. 范围

**必须交付**

1. **工作日志 v2（日报重做）**：读取「队列任务结果 + DSH 会话真实内容」，输出具体、有结论、可读的工作日志，不再是状态计数与空话。
2. **晨间简报 v2**：基于昨天的工作日志 + 会话内容，输出「昨天发生了什么 / 今天建议先做（1–3 件，可一键入队）/ 等你处理 / 提醒」，并输出结构化建议 JSON 供 UI 一键采纳。
3. **复盘 v2**：读取本期工作日志 + 任务真实结果 + 用户纠正，输出「做了什么 / 反复出现的问题（带证据）/ 有效做法 / 下个周期只改 3 件事 / 可固化规则与技能」。
4. **极简今日页**：砍到 3 块（今日简报 / 等你处理 / 进行中），去掉右栏与 5 个附属模块；Header 精简；任务看板去掉 5 张 KPI 卡，改为一行状态条 + 单个全局搜索。
5. **回顾合并**：日报 + 复盘 + 经验 + 技能合并到一个「回顾」抽屉的 4 个 tab（日志 / 复盘 / 经验 / 技能），页头「日报/复盘」两个按钮移除。
6. 测试、README、locale、版本号 0.7.0、Git commit + tag `v0.7.0` + 推送（Lead 收口）。

**非目标（继续顺延）**：结果反馈👍👎、待验收、例行任务/模板、成本预算、项目/目标、全量检索、任务时间线。不要做。

## 2. 工作日志 v2（`host/reports.js`）

### 2.1 数据采集（关键：读真实内容）

- 新增异步采集：对当天有活动的 **DSH 会话任务**（`source === 'session'`）用 `bridge.transcript(sessionId)` 取真实内容，每个会话提取：
  - `ask`：第一条 user 消息（≤400 字，去掉插件 inject 的历史经验段落）；
  - `answer`：最后一条 assistant 消息（≤1500 字；过长取前 1500）；
  - 上限 **8 个会话**，按当天活动时间倒序；会话读取失败静默跳过。
- 队列任务：
  - `done/failed/cancelled`：`result.finalAnswer`（≤1500 字）或 `error`；
  - `running/paused/blocked/pending`：`lastMessage`/`error` + 状态；
  - 想法（idea）当天新建的也算「今天记下的想法」。
- 若当天没有任何任务/会话：仍生成一份简短日志（「今天没有记录到工作活动」+ 明天建议从队列/想法挑 1 件），不要报错。

### 2.2 Prompt（重写 `buildAiSummaryPrompt`，函数名可保留）

角色：你是用户的私人助理，写**工作日志**，不是状态报告。

硬性要求：
1. 第一行 `# YYYY-MM-DD 工作日志`；严格四个二级标题、顺序固定：
   - `## 一、今日要点`
   - `## 二、逐项记录`
   - `## 三、待跟进`
   - `## 四、明天建议`
2. **今日要点**：3–5 条，每条必须是具体结论/产出（做了什么、发现了什么、交付了什么），允许写具体数字、文件、文档、链接、结论；**禁止**「完成 X 项 / 整体平稳 / 顺利推进」这类空话。
3. **逐项记录**：每个任务/会话一条，格式 `- **标题**：你交代了……；我做了……；结论/产出是……`，每条 1–3 句；会话任务要写清用户实际问的是什么、最后结论是什么，**不能只写标题**。
4. **待跟进**：只写真实未完成/待验证/等对方的事；没有就写 `- 无`。
5. **明天建议**：1–3 条具体动作，能直接执行或决策。
6. 总长 600–900 字；不写 token/模型/耗时/优先级/会话 ID；不要代码围栏；不要编造数据之外的内容。
7. 输入数据里会提供「队列任务」「DSH 会话摘要」「想法」；要优先使用会话摘要里的真实内容。

### 2.3 兜底与规整

- `buildDailySummary`（本地兜底）升级：按「要点 / 逐项 / 待跟进 / 明天建议」四段，逐项写入 `finalAnswer` 首句或 `lastMessage`（不能只有状态与标题）。
- `normalizeAiSummary`：四段标题改为新标题；允许内容更具体（保留数字/结论/文件/链接），仅过滤 token/模型/路径/会话 id 等技术行；每节条数上限放宽（要点 6、逐项 12、待跟进 8、明天建议 4）；总长上限 3000 字，单条 ≤300 字。
- 文件名/路径/API 不变（仍 `reports/YYYY-MM-DD.md`）；UI 显示名改为「工作日志」。

## 3. 晨间简报 v2（`host/briefs.js`）

### 3.1 数据

- **读取昨天的日报文件**（`reports read`）作为主要上下文（≤1500 字）；没有则跳过。
- 昨天的 DSH 会话摘要（同 §2.1 的 `ask/answer` 提取，上限 6 个）与昨天的任务结果。
- 当前：pending 队列、idea 想法（最近 3 个）、blocked/paused/failed（带等待时长）、running。
- 待采纳技能候选数。

### 3.2 输出结构

```
# YYYY-MM-DD 晨间简报

## 一、昨天发生了什么
- 2–4 条具体结论（优先来自日志/会话摘要，不写状态计数）

## 二、今天建议先做
- 1–3 条：**做什么** — 为什么是它（依据昨天的未完成、队列、想法、截止等）
## 三、等你处理
- 有就列（≤4 条），没有写「- 无」

## 四、提醒
- 简短 1–3 条（等待超时、技能候选、今天定时节点）
<<<SUGGESTIONS_JSON>>>
[{ "title": "≤60字", "reason": "≤80字", "prompt": "≤500字，可直接作为任务描述", "priority": "urgent|high|normal|low" }]
<<<END_SUGGESTIONS>>>
```

- `SUGGESTIONS_JSON` 解析后**从 markdown 中剥离**；解析失败不影响简报落盘。
- 结构化建议持久化：`store.updateMorningBrief({ lastSuggestions })`；`normalize` 保留数组（≤3 条，字段清洗、priority 归一）；`/state.settings.morningBrief.lastSuggestions` 对客户端可见。
- 建议兜底：模型没给合法 JSON 时，从 pending（最多 2 条）+ 最新 idea（1 条）生成建议（title=任务标题、reason=「已在队列/想法」、prompt=任务 prompt）。
- 长度：正文 400–700 字；固定四段；每段标题文字不可改。`normalizeMorningBriefText` 适配新标题并保留 `<<<SUGGESTIONS_JSON>>>` 之外内容。
- Webhook `morningBriefMarkdown`：标题下加「今天建议：」3 条（含 reason），正文摘要 ≤600 字，末尾保留路径。
- 其余定时/409/兜底/文件逻辑不变。

## 4. 复盘 v2（`host/evolution.js`）

- 数据采集追加：本期覆盖窗口内的**工作日志文本**（读取 `reports` 目录对应日期文件，最多 7 篇、每篇 ≤800 字）；任务行改用更具体的结果摘要（`finalAnswer`/`error`，≤300 字）；纠正数据保持。
- Prompt 固定五段（标题文字与顺序固定，旧的「做得好/错误与用户纠正」替换）：
  - `## 一、这段时间在做什么`：按项目/主题分组，2–4 组，带具体产出与结论；
  - `## 二、反复出现的问题`：每条必须带证据（具体任务/会话标题）；没有就写「- 无」；
  - `## 三、有效的做法`：可复用的方法，2–4 条；
  - `## 四、下个周期只改 3 件事`：具体、可执行、可验证，恰好 1–3 条；
  - `## 五、值得固化的规则/技能`：与 lessons/skills 呼应，可写「- 无」。
- 经验/技能 JSON marker 与合并逻辑保持不变（最多 40 经验 / 20 技能、去重、ask/auto 模式不变）。
- 兜底报告同步使用新五段标题。
- 长度 700–1100 字；不写 token/模型/路径。

## 5. 极简今日页（`client.js`）

### 5.1 Header（精简）

一行：左侧品牌「任务管家」+ 副标题「你交代，我盯着」；中间分段控件「今日 / 任务」；右侧**仅保留**：通知铃铛（未读数）、「回顾」按钮（打开合并抽屉，技能候选显示徽标）、设置、「＋ 新建」。移除：执行中药丸、自动执行开关（移到任务页状态条）、日报按钮、复盘按钮、头像位（若存在）。

### 5.2 今日页（3 块 + 页脚）

```
11月11日 · 周三    早安，今天也交给我。
[ 交代一件事…回车记下，稍后安排            （记下）]
┌ 今日简报 ────────────────────────────────┐
│ 3 行以内摘要（去掉 Markdown 标记）          │
│ 今天建议：① 做什么 — 为什么  [加入队列]     │
│ ② ...                                     │
│ [查看全文] [重新生成]                      │
└──────────────────────────────────────────┘
┌ 等你处理（仅当有内容时出现，最多 3 条） ┐
┌ 进行中（仅当有任务时出现，紧凑一行一条） ┐
页脚小字：今天完成 2 件 · 查看工作日志 · 任务看板
```

- **今日简报块**：取 `/state.briefs` 最新一篇 + `settings.morningBrief.lastSuggestions`：
  - 有今日简报：显示正文前 3 条要点（`stripMarkdown`）+ 建议列表（每条「做什么 — 为什么」+「加入队列」按钮 → POST `/tasks` status=pending, title/prompt 来自建议；成功后 toast 并刷新）；按钮「查看全文」（打开回顾抽屉的日志 tab 并选中今天简报）、「重新生成」。
  - 今日未生成：显示「今天还没有晨报」+「立即生成」+「查看昨日日志」（若有）。
  - 已关闭：显示「晨间简报已关闭」+「去设置」。
  - Host 不支持（无 briefs 字段）：显示「当前 Host 版本不支持晨间简报」灰态，不崩溃。
- **等你处理**：blocked/paused/failed + 技能候选；有内容才渲染；每条一行（类型标签 + 标题 + 主操作 + 打开）；最多 3 条 + 「还有 N 条」；无内容时整块不出现（不要空卡）。
- **进行中**：running 任务，紧凑行（标题 + 已运行时长 + 打开会话/暂停），最多 3 条；无内容时整块不出现。
- **页脚**：`今天完成 N 件` + `查看工作日志`（打开回顾-日志）+ `任务看板`（切到任务）。
- **删除**：今日焦点、今日完成大卡、今日小账、快捷入口、消息推送卡、通知记录卡（通知记录入口移到铃铛 popover 底部「通知记录」）。「我在盯着」「执行中 pill」删除。
- 响应式：单栏即可（无需右栏）；窄屏只做间距压缩。

### 5.3 回顾抽屉（合并）

- 页头「回顾」打开抽屉（宽度 `min(960px,100%)`），4 个 tab：**日志 / 复盘 / 经验 / 技能**。
  - 日志：复用现有日报列表 + Markdown + 立即生成（把「日报」文案统一为「工作日志」，保留 `/reports*` 端点）。
  - 复盘 / 经验 / 技能：现有 EvolutionDrawer 三个 tab 原样迁移。
  - 技能候选徽标/「立即复盘」/经验增删启停/技能采纳等全部保留。
- 移除独立 ReportsDrawer 入口（组件可保留内部复用，但不得再注册独立 header 按钮/弹窗入口）。
- 设置弹窗分区顺序保持 v0.6（执行 / 桌面提醒 / 消息推送 / 工作日志 / 晨间简报 / 复盘与沉淀 / 数据备份）；「日报」文案统一改为「工作日志」相关文案（如「工作日志时间」「启用工作日志」）。

### 5.4 任务页（降噪）

- 移除 5 张 KPI 卡，改为一行状态条：`想法 N · 队列 N · 进行中 N · 已结束 N`，右侧保留「自动执行」小开关 + 一个**全局搜索框**（跨列过滤标题/描述/目录/结果）。
- 移除每列内的搜索框（保留每列的漏斗筛选按钮与筛选逻辑，列头 `x/y` 逻辑保留）。
- 卡片上下文/结果摘要统一 `stripMarkdown`（去掉 `#`、`**`、反引号、分割线），不得再显示裸 Markdown 标记。
- 其余看板交互（拖拽、列内排序、状态/优先级/来源筛选、详情抽屉、动作）全部保留。

### 5.5 文案与命名（zh/en 同步）

- 「日报」→「工作日志」（页头入口、tab、设置分区、按钮、提示、生成结果 toast 等；API/文件名不变）。
- 「复盘」保持；页头按钮文案「回顾」；新 tab：日志 / 复盘 / 经验 / 技能。
- 新增 key：`review`（回顾）、`journalTab`（日志）、`briefTitle`（晨间简报）、`briefSuggest`（今天建议）、`briefJoin`（加入队列）、`todayFooterDone`、`viewJournal`、`todayDone`；现有 key 能用则复用。
- 今日页不再使用的 key 可保留（不强制删除），但不得再在今日页渲染。

## 8. 已知边界

- 会话内容摘要会截断（每条 ≤1500 字），超长会话只能看到最后结论。
- 工作日志/晨报/复盘仍是 AI 生成：失败/超时/结构不合规时用本地兜底，兜底质量低于 AI。
- 今日页只显示「今天/需要动作」的信息，完整历史在任务页与回顾抽屉。
- 会话被删除后无法读取内容（与 v0.6 一致）。
