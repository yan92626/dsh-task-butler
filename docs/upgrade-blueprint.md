# 任务管家 · 价值升级蓝图（v0.5.0 → v0.6 / v0.7 / v0.8）

> **一句话**：把「帮你记录任务的看板」升级为「替你盯着、替你排期、替你收尾的 Agent 秘书」。

> 本文是产品方案，不改代码。依据：真实运行数据（10 任务 / 4 篇日报 / 1 篇复盘 / 4 条经验 / 2 个技能候选）、代码审计、界面审计、14 个同类产品的官方文档、以及一版高保真设计稿。

> ✅ 已实现：今日工作台（今日 / 任务双视图）、待你处理 + 通知中心、一句话快捷捕获、晨间简报（Host 生成 + Webhook + 站内卡片 + 设置区）、优先级接入入队排序、DSH 会话任务结果回填、`/webhook/log` 前端接通、命名第一轮（想法 / 队列 / 进行中 / 已结束、等你回复、下一个执行、停止本轮、自动执行等）。

## 0. 一页结论

**诊断**：现在不像秘书，因为它的每个功能都在**增加信息**（卡片、状态、统计、报告），却几乎没有**替你做决定**。用户必须自己发起任务、自己扫列找阻塞、自己读结果、自己记住教训——心智负担没有下降，只是被搬进了插件。

**三个升级支柱**：

| 支柱 | 解决的问题 | 核心动作 |
|---|---|---|
| **① 首屏换脑：今日工作台** | 「打开了不知道看什么」 | 默认页从四列看板改为：待你处理 → 今日焦点 → 进行中 → 今日完成（带一句话结果） |
| **② 主动节奏：晨报 + 日报 + 复盘** | 「不打开就没有价值」 | 每天 08:30 晨间简报（计划）推飞书、21:00 日报（记录）、复盘（沉淀）；把已有的日报/复盘/通知串成一天 |
| **③ 交代一次，长期复用：例行任务 + 结果资产** | 「每件事都要我重新说一遍」 | 例行任务/模板（每天/每周自动入队）、结果反馈（👍/👎）、一键沉淀为经验/技能/模板、完成结果可检索 |

**如果只做三件事（推荐）**：

1. **今日工作台**（含「待你处理」聚合 + 一句话快捷捕获）——让每次打开都有明确的事可做、可拍板；
2. **晨间简报**（复用日报引擎 + Webhook，08:30 主动送达）——不打开插件也能感到秘书在上班；
3. **例行任务 + 模板**（每天/每周自动入队）——从「我递任务」变成「它在等我确认」，这是最像秘书、也最难被普通看板替代的能力。

**路径**：v0.6「今日」→ v0.7「主动」→ v0.8「资产」。P0 大部分只动浏览器半与现成数据，不新增状态；P1/P2 才动 Host 数据模型。详见 §6 路线图。

**命名总方向**：产品名保留「任务管家」（刚由「私人秘书」改过一次，不再改）；把**工程语汇换成秘书语汇**：队列→队列（可保留）、阻塞→**等你回复**、置顶→**下一个执行**、打断→**停止本轮**、自动领取→**自动执行**、自我进化→**复盘与沉淀**、通知/消息通知→**桌面提醒 / Webhook 推送**。列名：**想法 / 队列 / 进行中 / 已结束**。

## 1. 诊断：为什么现在像「只是看板」

### 1.1 真实数据画像（2026-11-10，rev 1119）

- 10 个任务：done 8 / running 1 / idea 1；**session 导入 5 个、队列发布 5 个**。
- 8 个「已完成」里 5 个是 DSH 会话自动归档，**且这 5 个没有 result / 耗时 / tokens**（`finalizeResult` 只覆盖队列任务）——看板上最醒目的历史列，一半是空壳。
- 3 个真正跑完的队列任务累计 **42.2 万输入 / 35.3 万输出 / 3308 万缓存读 tokens**，但这些数字只出现在单卡与抽屉里，没有任何聚合、预算或成本含义。
- 4 篇日报、1 篇复盘、4 条经验、2 个技能候选（0 个启用）；`dailyReport.enabled=false`、`evolution.enabled=false`——**用户认可的两个能力目前处于静默关闭状态，首屏没有任何提示与入口**。
- 只产生过 1 条 Webhook 投递记录（`claimed`）；`GET /webhook/log` 已实现但前端从未调用。

### 1.2 首屏在回答错误的问题

现状首屏 ≈ 80% 面积是「历史存档 + 累计统计」：5 张 126px 的粉彩 KPI 卡 + 四列看板。它回答的是「我的任务分别在哪个状态」，而用户此刻真正的问题是：

| 优先级 | 用户的问题 | 现状 |
|---|---|---|
| P0 | **什么需要我？**（阻塞 / 待审批 / 失败 / 待验收） | 无入口；阻塞卡混在「处理中」列里靠颜色找 |
| P0 | **今天该做什么？** | 只有「执行中 1」一个数字 |
| P1 | 进展如何 / 昨天怎样？ | 面积最大，但只回顾、不决策 |

三个补充证据：

- 统计条与列头**同一数字重复出现**，且口径不一致（KPI「已完成 2 + 失败 1」vs 列头「已归档 4」，含已取消 1），用户会算出矛盾。
- 一行四个列内搜索框是最大视觉噪音；每张待排队卡片 hover 出现 **7 个 26px 图标**（低于 44px 触控标准）。
- 卡片元信息最多 5 项、字号 10–10.5px，预览图已出现 `deepseek-flash · m` 被裁断——用户先看到的是技术噪音，而不是「这件事结果如何」。

### 1.3 四个结构性断点

1. **捕获太重**：发布任务必须填标题 + 描述 + 工作目录三个必填项。它适合「已经想清楚的任务」，不适合「先记下来」。于是你只会在已经决定要做时打开它——**插件变成了执行工具，而不是入口**。
2. **决策没有入口**：`blocked` 只被检测到（`ask_user_question` 未答）并推一条 Webhook，但站内没有「现在需要你」的队列，也没有一键回到对话。
3. **结果不闭环**：任务完成 = 一个 `finalAnswer` 字段。没有验收、没有反馈、没有「值不值得」；复盘产出 4 条经验、2 个技能候选后，**没有任何机制让它们作用于下一次任务**（设计上默认不注入 prompt，是对的；但「只写不读」让投入归零）。
4. **只在面板可见**：价值全靠用户主动打开侧栏面板 + 扫看板。唯一的主动触达是 Webhook，且 6 类事件默认全推（通知疲劳风险），也不回流到面板（应用内没有通知中心 / 未读 / 角标）。

### 1.4 已有资产被浪费（可直接捡起来）

- **会话结果不回填**：50% 的任务没有结果、耗时、tokens。
- **`group` 分组**：全链路持久化，但浏览器半 0 引用（static-check 甚至禁止它出现）——现成的项目维度。
- **`priority` 优先级**：只展示，不参与领取顺序——用户选了「紧急」却不会先跑，预期落差。
- **经验/技能**：只写不读；2 个候选技能待采用但无主动提示。
- **webhook 投递日志**：后端已有，前端没接。
- **state 里的 tokens/耗时/轮次**：没有日/周/月聚合，也没有「人工介入次数、等待时长、一次通过率」这类真正反映秘书价值的指标。
- **`/state` 全量轮询（1.5s）+ 每次保存全量写盘 + 复制恢复点**：新增事件/统计若继续塞进 state，会放大轮询与备份成本（需独立轻量端点/事件文件）。

### 1.5 一个判断：价值 = 减少心智负担

衡量一个秘书，不是看它把信息摆得多整齐，而是看它让你**少想多少事**。当前插件的每个功能都在让你多想一点。升级的每一项都应该能回答一个问题：**它替你省掉了哪一步？**

| 省掉的那一步 | 对应功能 |
|---|---|
| 少扫描（不用自己找阻塞/失败） | 待你处理 |
| 少选择（不用决定从哪件开始） | 今日焦点（最多 3 件，可换一批） |
| 少记录（不用填 3 个必填项） | 一句话快捷捕获 |
| 少记忆（不用记昨天做了什么） | 晨报 / 日报 / 复盘 |
| 少重复交代（同样的事每周说一遍） | 例行任务 + 模板 |
| 少阅读（不用读完整会话） | 结果摘要 + 结果证据 + 👍/👎 |
| 少担心（无人值守会不会失控） | 预算 / 超时 / 急停 / 等待时长 |
| 少翻找（那次结论是什么） | 全量检索 / 问历史 |

## 2. 重新定位：Agent 秘书台，一天三次

### 2.1 定位语

- 对用户：**「你交代，我盯着。」**（现有副标题「任务、会话与日报，都替你盯着」的问题是漏掉了复盘/经验/技能，且「盯着」像监控）
- 首页问候（设计稿已采用）：**「今天也交给我。你只需要决定，先做哪一件。」**

### 2.2 心智模型：一天三次节奏

```
08:30 晨间简报（它先说）    → 昨天完成/失败、今天建议焦点、待你处理、风险
      白天（它干活）        → 例行任务自动入队；执行中不需要你看；有阻塞才找你
21:00 工作日报（它记录）    → 今日概览 / 完成 / 进展与问题 / 明日计划
晚间或每周 复盘（它学习）   → 做得好 / 错误与纠正 / 经验规则 / 技能候选
```

日报的第 4 段「明日计划」正好成为第二天晨报的输入——这就能把现有能力串成一个闭环，而不是三份各自为政的 AI 报告。

### 2.3 三条产品原则

1. **Only what needs you**：默认只显示需要动作的事 + 今天的事；完整历史留在「任务」视图。
2. **输出优先于面板**：日报/复盘/简报这类可读输出是核心资产，不是藏在 header 按钮里的附庸。
3. **可核对、可关闭、不假主动**：每个「主动」都要能回答数据从哪来、什么时候触发、能不能关；不做偷偷改计划、不做无法验证的「节省时间」数字。

### 2.4 用这些指标判断升级是否成功

- 7 天内至少 5 天收到/打开简报（习惯）。
- 「待你处理」平均等待时长下降（响应速度）。
- 任务发布到进入执行的中位时间下降（捕获有效性）。
- 完成任务的 👍/👎 反馈率 > 30%，一次通过率上升（质量与学习）。
- 重复交代次数下降（例行任务覆盖率）。
- 打开插件后 10 秒内能说出「现在该做什么」（可用性）。

## 3. 功能蓝图

> 成本口径：S ≈ 0.5–1 人日，M ≈ 2–4 人日，L ≈ 1–2 周（含 Host、浏览器半、测试、文档同步）。「Host」= 数据/调度层，「UI」= 浏览器半，「Tool」= Agent 工具。

### P0（v0.6，1–2 周）：让它每天有用

#### 3.1 今日工作台（默认首屏）

- **是什么**：新增「今日」视图作为默认页；看板降级为「任务」页。结构（见 `docs/design/today-mockup.html`）：
  1. 顶部日期栏：`11月10日 · 周二`、问候「早安，朋友。」、右侧「我在盯着：今天已替你处理 4 件」「⌘K」「🔔」；
  2. **一句话快捷捕获**：输入「交代一件事…回车记下，稍后安排」，回车即存为「想法」（`status: idea`），描述/目录可后补；
  3. **晨报条**：一句话摘要 +「查看晨报」+「昨日完成 4 件」；
  4. **待你处理**（P0）：阻塞/暂停/失败/待采用技能，一行一句 + 主操作按钮 +「查看对话」；
  5. **今日焦点**：AI 排序的 3 件（可换一批），每件带推荐理由（承接昨天未完成 / 截止今天 / 会议相关），一键「加入队列」；
  6. **进行中**：实时计时 + 进度 + 「预计 12:40 完成」；
  7. **今日完成**：结果一句话 + 用时 + 👍/👎 +「沉淀为经验」；
  8. 右栏：**今日小账**（完成/进行中/待你处理/本周省下时间/tokens）、**例行任务**、**快捷入口**。
- **为什么值**：这是「只是看板」抱怨的直接解药——首屏三问（谁等我 / 今天做什么 / 进展如何）一次回答，且所有区块只显示今天或需要动作的事。
- **MVP 做法**：纯前端用 `/state` 派生即可（blocked/paused/failed/idea/running/done 都在）；「今日焦点」先按「有截止时间 > 承接链 > 排队顺序」规则排序，后续再接 AI 排序；晨报条先用最近日报 + 计数拼一句话。
- **成本**：M（UI 为主，Host 不动）。**风险**：与看板信息重复——规则是「今日只显示今天/需动作，完整历史只在任务页」。

#### 3.2 待你处理（Needs you）+ 通知中心 + 角标

- **是什么**：一级入口，聚合「阻塞（等回答/等审批）、暂停待决定、失败待重试、待采用技能、等待超时」；每条显示**在等你多久**，并可直接「回一句 / 重试 / 继续 / 跳过」。侧栏入口显示数量角标；面板内铃铛展示事件流（领取/完成/失败/阻塞/日报/复盘），未读可标已读。
- **为什么值**：无人值守场景里，用户真正要管的就是「什么时候该我出手」。这是从「看板」变成「异常驱动工作流」的分水岭；外部标杆（Claude Code 的 Needs input 置顶、ChatGPT Activity 的 waiting 分组、Cursor 移动端 inbox）都把这件事放在第一屏。
- **MVP 做法**：数据全部现成（`blocked` 由未答 `ask_user_question` 判定；`/transcript` 可取问题原文；可用 `/chat` 发回复）。注意：bridge 没有专门的「回答提问」方法，内联回复走 `/chat` 投递消息，**需实机验证能否结束原提问**；先做「一键打开对话并聚焦输入框」的降级路径。通知中心先用 `/state` 派生 + `localStorage` 记 lastSeenAt；后续再接 Host 事件流（`GET /webhook/log` 已有，成本极低）。
- **成本**：M（UI 为主 + 可选 `/events` 轻量端点）。**风险**：中（阻塞的「回答」语义需实机验证）；通知分级必须同时做，否则会制造通知疲劳（见 §6.5）。

#### 3.3 快捷捕获 + 收件箱化

- **是什么**：默认页顶部一句话输入；回车即存为「想法」；「想法」列改造成收件箱语义（先收、后分流：今日焦点 / 队列 / 哪天做 / 删除）。发布弹窗保留给「批量 / 需要目录 / 串联」的高级场景。
- **为什么值**：捕获成本决定系统会不会被信任。现在是三个必填项；升级后是 0 个必填项。
- **MVP 做法**：`POST /tasks` 已支持 `status:'idea'`、`priority:'normal'`；cwd 传最近一次使用的目录（客户端已有 `lastDir` 逻辑可复用）；描述可空。
- **成本**：S。**风险**：cwd 猜测错误——在卡片上明确显示「使用默认目录」并允许一键修改。

#### 3.4 结果优先的卡片 + 今日完成改写

- **是什么**：卡片第二行改为**一句话结果/下一步**（已完成任务显示 `result.finalAnswer` 首句；进行中显示当前进展摘要；待你处理显示「在等你回复」）；元信息从 5 项减到 ≤3 项（结束时间、耗时、模型），tokens/轮次/目录收进抽屉或 tooltip。
- **为什么值**：用户关心的是「它做成了什么」，不是「它在哪个目录跑的什么模型」。
- **MVP 做法**：`result.finalAnswer` 已在 `/state`（截断 4k）；先取首句/首 60 字。顺带修复 50% 会话任务无结果的问题（见 3.7）。
- **成本**：S。**风险**：无。

#### 3.5 全局搜索 + ⌘K（轻量版）

- **是什么**：去掉四列各自的搜索框，改为顶部一个全局搜索（标题/描述/结果/目录，结果按状态分组，关键词高亮）；`⌘K` 打开命令面板：记一件 / 搜索 / 生成日报 / 立即复盘 / 打开待你处理 / 切换自动执行。
- **为什么值**：砍掉 4 个输入框的视觉噪音，同时给高频路径一个短入口；为后续全量检索（P2）留位置。
- **MVP 做法**：纯前端；复用 `matchesSearch`，扩展到 `result.finalAnswer` 与来源筛选；`searchPlaceholder`、`searchClear` 等未使用文案键正好复用。
- **成本**：M（接近 1 天）。**风险**：无 DOM 测试，键盘与焦点陷阱需人工验收。

#### 3.6 视觉降噪 + 命名第一轮

- 统计条：5 张 126px KPI 卡 → 日期栏一行内联数字（完成 / 进行中 / 待你处理），或最多 4 张 88px；**每个数字只出现一次**。
- 收敛色相：语义色 3 个（待办紫 / 需你琥珀 / 完成薄荷）+ 失败玫红仅局部使用；圆角 3 档（24 / 16 / 999）；阴影 2 档；元信息字号 ≥11.5px。
- 卡片动作：7 个图标 → 2 个主操作 +「•••」；触控 44px。
- 命名：见 §5，先改用户高频可见的一批（列名、状态词、动作词、两个「通知」）。
- **成本**：S–M。**风险**：命名涉及约 40 个 zh/en key，需同步 `tests/static-check.mjs` 的字符串契约。

#### 3.7 数据 quick wins（随手修，收益立刻可见）

| 项 | 说明 | 成本 |
|---|---|---|
| 会话任务结果回填 | session 任务 running→done 时调用 `finalizeResult`（复用 `bridge.summarize`），50% 任务立刻有结果/耗时/tokens | S |

### P1（v0.7，2–4 周）：让它主动干活

#### 3.8 晨间简报（08:30）

- **是什么**：每天固定时间生成一份可推送的「今日简报」：① 昨天完成/失败/未完成 ② 今天建议焦点 3 件（队列 + 想法）③ 待你处理 N 件 ④ 风险（等待超时、长期无进展、技能候选待采用）⑤ 明日计划回读。走现有 Webhook（飞书等）推送，同时进「今日」页常驻卡片；可改时间、可关闭、可「现在生成」。
- **为什么值**：这是投入产出比最高的「秘书感」功能：复用日报引擎 + Webhook，几乎不新增数据，却把「你不打开插件」的时间也变成价值。外部标杆（Lindy Daily Brief、Claude Code scheduled tasks、Sunsama 晨间规划）都验证了这个模式。
- **MVP 做法**：复制日报管线：`collectData` 增加「未来视图」数据源（pending/idea/blocked/failed/技能候选）；prompt 固定结构；文件名 `morning-YYYY-MM-DD.md`；settings 增加 `morningBrief{enabled,time}`；Webhook 新增事件 `morningBrief`。
- **成本**：M。**风险**：与日报「明日计划」内容重复——晨报只写「今天做什么 + 需要你什么」，不写今日完成；日报只写「今天做了什么」，两者分工明确。

#### 3.9 例行任务 + 任务模板

- **是什么**：任务支持「例行」属性：每天 / 每周 / 每月 / 每隔 N 天 + 时间，到点自动创建并入队；支持从历史任务「一键设为例行」。模板库先内置 5 个：晨报、周报、收件箱清零、依赖更新检查、失败任务重试。任务卡显示「例行」徽章与下次运行时间。
- **为什么值**：从「我每天/每周记得交代」变成「它在固定时间等我确认」。这是最像秘书、也最难被普通看板替代的差异化能力。
- **MVP 做法**：复用 `reports`/`evolution` 的 30s due 检查 + `nextRunAt` 持久化；`templates[] = {id,name,title,prompt,cwd,schedule,defaults}`；定时生成 pending 任务（自动执行与否可配置）；补跑规则：Host 关闭期间错过的，重开后只补最近一次，不堆积。
- **成本**：L（含时区/DST、漏跑与重复创建、与 DSH 自带「定时任务」边界划清）。**风险**：高；建议先做「每天/每周」两档 + 明确「Host 关闭不执行」的提示。

#### 3.10 结果证据 + 待验收

- **是什么**：任务完成不是只有一段总结，而是固定四块：① 产物（文件/链接/PR）② 改动摘要 ③ 验证方式（测试/预览/人工确认）④ 用量（耗时/轮次/token，已有）。`done` 之后可进入「待验收」，一键「验收通过 / 打回重做」（打回时自动生成承接任务）。
- **为什么值**：「完成 ≠ 做对」。无人值守的信任只能来自可核对的结果；外部标杆（Cursor 的 PR artifacts、Claude Code 的 checkpoint、ChatGPT dots 明确说「run 完成不等于交付」）都在补这一块。
- **MVP 做法**：结果区四块先用现有 `finalAnswer` + 会话文件操作提取（能从 transcript 识别写文件动作即可，识别不到就留空）；`done` 保持现状，新增「待验收」仅作为筛选/标记，不新增状态机状态（降低风险）。
- **成本**：M。**风险**：中；产物自动识别准确率有限，先做「人工确认」路径。

#### 3.11 反馈 → 沉淀闭环

- **是什么**：今日完成行/结果区加 👍/👎 + 可选一句话评价；👎 时问「哪里不对」；「沉淀」按钮把结果变成：经验规则 / 技能候选 / 任务模板 三选一。经验页显示「来源任务、最近命中、被纠正次数」，支持「在新建任务时手动引用经验」（默认不自动注入，延续 v9 的安全取舍）。
- **为什么值**：现有 4 条经验 + 2 个候选技能「只写不读」是最可惜的既有投资。反馈是让复盘真正改进下一次任务的最小成本手段。
- **MVP 做法**：`task.feedback = {vote, note, at}` + `POST /tasks/feedback`；复盘 prompt 增加「用户反馈」数据块并优先提炼；经验加 `hits`、`corrections` 计数；「手动引用」在发布弹窗里加一个「参考经验」多选。
- **成本**：S（反馈）+ M（沉淀/引用）。**风险**：反馈稀疏、评价标准模糊——先只收集不承诺效果。

#### 3.12 工作小账 / 周报（价值与成本）

- **是什么**：右栏「今日小账」+ 每周一页「本周账单」：完成/失败/进行中、人工介入次数、平均等待时长、一次通过率、tokens（可选按模型单价估算费用）、经验/技能新增、例行任务节省的重复交代次数。**不做**「节省时间 = X 小时」这类无法验证的数字，除非用户自己填估算口径。
- **为什么值**：让用户看到「这个插件值不值得继续用」；也是周复盘和后续目标层的数据基础。
- **MVP 做法**：纯前端聚合 `/state` 即可先出「今日小账」；周报复用日报管线（区间化 `collectData`）+ 本地兜底；费用估算需要用户在设置里填单价（默认不估算）。
- **成本**：M（周报）/ S（今日小账）。**风险**：数据质量（会话任务无 usage、duration 不可信）——先做 §3.7 的修复。

#### 3.13 成本预算与刹车（信任底座）

- **是什么**：设置里配置每日/每周 token 或费用上限；接近上限时提醒，超过时自动暂停领取并推送一条通知；支持「急停」（暂停全部执行、保留队列）、「超时自动中止」（运行超过 N 分钟/小时的任务转阻塞或失败）。
- **为什么值**：无人值守最怕失控。当前 3308 万缓存读 tokens 已在 state 里，聚合几乎没有采集成本；这是把「敢不敢放手」变成「可以放手」的关键。
- **MVP 做法**：`settings.cost{budget, prices, enforce}`；`claimPending` 前检查当日已用；新增 Webhook 事件 `budget`。会话任务无 usage 时按「未知」处理（不阻塞，只提示）。
- **成本**：M。**风险**：中；强制停工会卡住队列，默认只提醒、用户可开「自动暂停」。

### P2（v0.8+，1–2 月）：让它成为资产

#### 3.14 项目 / 目标层

- **是什么**：MVP 先把已有的 `group` 暴露出来：发布/编辑可选分组、看板按分组筛选、日报/周报按分组汇总（`static-check` 需移除「禁止 group」断言）。完整版再做 `goals[]`：目标、进度、截止、关联任务，首页显示目标进度而不是任务数。
- **为什么值**：用户觉得「只是个看板」，本质是任务没有「为什么做、做到哪了」的上层。先做分组 + 周报是性价比最高的入口；目标层要防止变成又一个 OKR 工具（产品原则：轻量，不做绩效）。
- **成本**：M（分组）/ L（目标）。**风险**：目标与项目语义混淆——建议对外只用一个词「项目」，目标作为项目里的一个说明字段。

#### 3.15 全量检索 + 问历史

- **是什么**：一个入口搜遍任务、结果、对话、日报、复盘、经验；后续加「问秘书」：基于检索结果回答「上次登录问题最后怎么解决的？」并给出来源任务链接。
- **为什么值**：数据资产的前提是找得到。现在只有列内搜索，跨历史等于没有。
- **MVP 做法**：先做任务级全量搜索（标题/描述/结果/经验/日报/复盘文本，Host 建轻量索引或每次按需扫文件）；「问历史」复用 Agent 会话 + 检索片段，结果只读、附来源。
- **成本**：M（搜索）/ L（问历史）。**风险**：`/state` 的 4k 截断与轮询体积——新搜索独立端点，不要塞进 `/state`。

#### 3.16 任务时间线 / 等待追踪 / 接管与交还

- **是什么**：每次状态变化（claim/pause/resume/retry/settle/chat/revive）记一条事件；抽屉里展示时间线；卡片显示「排队 2 小时」「等你 18 分钟」；任务可「接管」（人工处理中，暂停自动推进）/「交还」。
- **为什么值**：等待时长是判断是否介入的主要依据；时间线让复盘有事实基础。事件流同时是通知中心、统计、周报的地基（一次投入三处收益）。
- **MVP 做法**：独立 `events.jsonl`（append-only，上限 500–1000 条），不要走 `state.json` 全量 save（写放大）；API 只读最近 N 条。
- **成本**：M（与通知中心合做）。**风险**：跨重启一致性、事件量。

#### 3.17 优先级接入调度（或明确标注）

- **是什么**：二选一：要么让 pending 队列按「紧急 > 高 > 普通 > 低」排序领取（同优先级按现有顺序），要么在 UI 上明确「仅标记，不参与调度」。推荐前者——用户选了「紧急」却不会先跑，是直接的信任损耗。
- **成本**：S（排序）＋ 文档/测试同步。**风险**：改变既有调度语义，需在 README/API/tool 描述里同步。

#### 3.18 外部事件触发 / IM 双向 / 日历

- **是什么**：Webhook 入站（外部系统 POST 即创建/入队任务，如 CI 失败、监控告警）；飞书/企微通知支持「回复即处理」（回复 1 继续、回复 2 重试）；日历集成（把有截止时间的任务/例行任务映射到日程）。
- **为什么值**：让「有事才干活」成立；IM 双向把「通知」升级成「操作」。
- **成本**：L。**风险**：外部系统耦合与安全校验；建议等核心闭环稳定后再做。

## 4. UI/UX 升级

### 4.1 保留什么

现有视觉语言是用户在 v7 明确选择的（柔和现代卡片风：大圆角、柔光阴影、粉彩洗底、紫色渐变主按钮、明暗双主题），**不建议推倒重来**。做得好的：双主题同一套 token、状态色条 + 胶囊可扫读、`prefers-reduced-motion` / `:focus-visible` / `aria-modal` 等可达性基础、列内空状态与筛选闭环。升级是**换信息架构 + 降噪**，不是换装修。

### 4.2 降噪规则（一次性收紧 token）

| 项 | 现状 | 收敛为 |
|---|---|---|
| 语义色 | 5 张 KPI 卡 5 色 + 列 4 色 + 状态 ≈ 9 色 | 3 个语义色（待办紫 / 需你琥珀 / 完成薄荷）+ 失败玫红局部 |
| 圆角 | 24/22/20/16/14/13/999 共 7 档 | 24（容器）/ 16（卡片、输入）/ 999（胶囊） |
| 阴影 | 每类 2 层 + hover 再叠 2 层 | 2 档（静态 1 层、hover 加深） |
| 字号 | 元信息 10–10.5px | 正文 12.5px 起，元信息 ≥11.5px |
| 卡片元信息 | 最多 5 项、被裁断 | ≤3 项（结束时间、耗时、模型），其余进抽屉/tooltip |
| 数字 | 同一数字在 KPI/列头/药丸三处重复 | 一个数字只出现一次 |
| 渐变 | hero 卡 + 主按钮 + 处理中列边 3 处紫渐变 | 只保留主按钮渐变 |

### 4.3 今日工作台

完整视觉见 `docs/design/today-mockup.html`（明暗双主题、空状态/加载态演示、窄屏适配）与 `docs/design/README.md`。核心结构如 §3.1；与旧看板的差异：

- 旧：5 张 KPI + 4 列 + 列内搜索 → 新：日期栏 + 一句话捕获 + 晨报条 + 两个动作区块（待你处理 / 今日焦点）+ 进行中 + 今日完成 + 右栏小账/例行。
- 旧：首屏 80% 是历史 → 新：首屏只有「今天」和「需要你」。
- 旧：发布任务的弹窗是唯一入口 → 新：一句话捕获是默认入口，完整弹窗降级为高级路径。

### 4.4 导航与信息架构（推荐 4 个一级入口）

### 4.6 视觉方向的选择

界面审计给出两个方向：「秘书书桌·编辑风」（衬线标题、纸感、行式列表）与「指挥台·仪表盘」（现有卡片体系重排）。结论：

- **首屏采用「书桌感」的信息密度**（行式条目、更多留白、更少色块），但**沿用现有柔和卡片视觉**，不引入衬线字体与纸感底色（那是更大的品牌改动，可另做）。
- **「编辑感」只用于日报/复盘阅读区**：衬线标题 + 更宽行距 + 更好的 Markdown 排版——这是用户认可的价值区，值得单独打磨。
- 如果未来想整体换风格，建议作为独立视觉迭代（含 18 张预览图重做），不与本次 IA 升级混在一起。

## 5. 命名与文案优化

### 5.1 原则

- 去工程化：用「等人/等你/例行/收工/档案」这类秘书语汇替换「阻塞/领取/打断/承接」这类系统语汇。
- 一个概念一个词：现在「处理中 / 执行中」「已完成 / 已归档」「通知 / 消息通知」「沉淀 / 候选 / 采用 / 启用」都是同义多词，用户要重新学。
- 保留已建立认知：「任务管家」「日报」「复盘」「经验」「技能」不改名（改名成本高、收益低）。

### 5.2 命名映射表（首批，按用户可见度排序）

| 位置 | 现名 | 建议名 | 理由 |
|---|---|---|---|
| 面板副标题 | 任务、会话与日报，都替你盯着 | 你交代，我盯着 | 漏了复盘/经验/技能；「盯着」像监控 |
| 列 1 | 待开始 | **想法**（列提示：先记下，想好了再排期） | 这列就是「暂不执行的想法」；「待开始」听起来马上要开始 |
| 列 2 | 排队中 | **队列** | 名词列头更稳定；「领取」是系统动作 |
| 列 3 | 处理中 | **进行中** | 列内含 running/paused/blocked，「处理中」失真；与状态「执行中」区分 |
| 列 4 | 已归档 | **已结束**（或「档案」） | 这里是完成/失败/取消自动归集，不是用户手动归档 |
| 状态 | 阻塞 | **等你回复**（副文案：需回答 / 需审批；显示已等 18 分钟） | 「阻塞」是系统诊断词；用户只需知道「该我了」 |
| 状态 | 已暂停 | 已暂停（保留，hint 改：点继续接着跑，不会从头再来） | 通用词 |
| 动作 | 发布任务 | **新建任务**；快捷入口叫「**记一件**」 | 「发布」是向受众发布内容 |
| 动作 | 执行 | **立即执行** | 与「自动执行」区分 |
| 动作 | 置顶 | **下一个执行** | 实际是 `run-next` 插队，不是钉在列表顶部 |
| 动作 | 打断 | **停止本轮** | 不结束任务、保留会话，「打断」有攻击性且不说明后果 |
| 动作 | 移入排队中 / 移回待开始 | **加入队列 / 退回想法** | 双词列名太长，放不进卡内菜单 |
| 开关 | 自动领取 | **自动执行**（hint：队列按顺序自动开始） | 「领取」是调度内部隐喻 |
| 药丸 | 执行中 2 / 3 | **运行中 2/4（上限 4）** | 斜杠 + 两个词易读成分数；「并发」是工程词 |
| 设置分区 | 通知 | **桌面提醒**（浏览器通知） | 与「消息通知」并排最易混 |
| 设置分区 | 消息通知 | **Webhook 推送** | 明确技术边界与去向 |
| 模块 | 自我进化 | **复盘与沉淀**（设置分区名）；入口仍叫「复盘」 | 「自我进化」宏大且不说明内容 |
| 模块 | 技能沉淀模式：关闭/生成候选/自动启用；「采用」 | 技能生成：关闭/建议/自动；候选「采纳」 | 同一流程四套词，统一为「生成—建议—采纳—启用」 |
| 来源 | DSH 会话 | **来自会话**（tooltip：由 DSH 会话自动归档，只读） | 内部产品名；且这些卡不能执行/编辑 |
| 标签 | 承接 | **接续上一任务**（hint：把上一条的结果带给这条） | 「承接」书面且缺宾语 |
| 优先级 | 优先级（不参与调度） | **重要度**，并让它参与队列排序（§3.17） | 「选了紧急却不先跑」是预期落差 |
| 空状态按钮 | 记一个 | **记一件**（全局统一捕获动词） | 现有少有的口语化好文案，复用 |

## 6. 实施路线图与工程约束

### 6.1 版本节奏

| 版本 | 主题 | 范围 | 预估 |
|---|---|---|---|
| **v0.6** | **今日** | 今日工作台、待你处理 + 通知中心 + 角标、快捷捕获、结果优先卡片、全局搜索 + ⌘K、视觉降噪、命名第一轮、§3.7 数据 quick wins | 1–2 周 |
| **v0.7** | **主动** | 晨间简报、例行任务 + 模板、结果证据 + 待验收、反馈沉淀、工作小账/周报、成本预算与刹车、批量操作、键盘 | 2–4 周 |
| **v0.8** | **资产** | 项目/目标层、全量检索/问历史、任务时间线/等待追踪/接管交还、优先级接入调度、外部触发与 IM 双向 | 1–2 月 |

依赖关系：事件流（通知中心/时间线/统计共用）→ 成本与预算；组（group）→ 项目/目标；反馈 → 经验回环；模板 → 例行任务。

### 6.2 技术约束（必须尊重）

1. **浏览器半是单文件、无构建、无 JSX**：`client.js` 8751 行 / 454KB，新增 UI 全在这一个文件里；改动靠人工上下文，无 DOM 自动化测试。
2. **`tests/static-check.mjs` 是字符串契约测试**：API 路由、i18n 文案、列名、色板、动作枚举、版本号都在断言里；新增 UI/接口/颜色/文案必须同步改它，否则 CI 红。
3. **CI 只跑 static-check + Host 单测**，没有浏览器 DOM 测试；P0 的 UI 改动需要补一份 jsdom 交互测试（回收到仓储里，不要再「临时环境」）。
4. **`/state` 全量轮询（1.5s）+ 写放大**：新功能的数据（事件/统计/模板/目标）不要塞进 `/state`；用独立轻量端点或 `events.jsonl`。
5. **`STATE_VERSION=4` 兼容约定**：只加字段、normalize 容错、不轻易 bump；新字段必须进 `normalizeTask`/`normalizeSettings`，否则重启即丢。
6. **`ask_user_question` 没有回答 API**：内联回答只能通过 `/chat` 投递消息，需实机验证是否能结束原提问；先做「打开对话并聚焦输入框」的降级路径。
7. **插件生命周期**：Host 改动要 Plugin Manager 重新启用 bundle 或重启 Harness；浏览器半刷新页面。CI 不能覆盖真机定时器/技能注册，需要一轮人工验收。
8. **文档/契约漂移**：仓库缺失 `evolution-contract.md`（单测引用）与 `tests/client-dom.mjs`（static-check 引用）；动手前先修，避免二次漂移。

### 6.3 验收标准（v0.6）

- 1440 / 1024 / 780 / 640 / 390 五档宽度下，今日页首屏出现「待你处理 / 今日焦点 / 进行中 / 今日完成 / 晨报」五要素。
- 任务页首屏只有 1 个搜索入口；卡片元信息不截断；待排队卡可操作元素 ≤3 个。
- 键盘可完成「新建 → 加入队列 → 打开 → 暂停」全流程；`⌘K` 可搜索并跳转任务。
- 数据 quick wins 生效：会话任务完成后有结果与耗时；`/webhook/log` 在设置里可见。
- 命名第一轮落地且 zh/en 键对齐；`node tests/static-check.mjs`、`node --test tests/evolution-unit.mjs`、`python3 tests/api-check.py --base <harness>` 全绿。

### 6.4 建议分工

- **Lead**：契约（`docs/` 蓝图即规格）、`package.json`、locale、README、测试清单、最终验收。
- **ui-dev**：只改 `client.js`（今日页、待你处理、通知中心、捕获、搜索、命名文案）。
- **host-dev**：只改 `index.js` + `host/**`（会话结果回填、duration 修复、`/events`、晨间简报、反馈字段、预算）。

### 6.5 风险与反模式（明确不做什么）

| 风险 | 对策 |
|---|---|
| 通知疲劳（6 类事件全推） | 默认只开「需你处理 / 失败 / 日报」，其余默认关；支持摘要模式与免打扰时段 |
| 假主动（宣称在盯，其实没事发生） | 每条主动都要有数据来源、触发时间、关闭开关；不做「AI 自动找活」空壳 |
| 指标虚荣（节省时间/打卡） | 不显示无法验证的「节省时间」；改显示人工介入次数、等待时长、一次通过率 |
| 过度配置（工作流/多级依赖） | 内置 5 个模板 + 高级项折叠；链式依赖最多保持现有线性承接 |
| 自动重排骚扰 | 只建议不自动改用户计划；优先级接入调度要可预期 |
| 「完成」即成功 | 引入「待验收」与反馈，done 只是「这一轮跑完」 |
| 记忆黑洞 | 经验可查、可纠错、有来源、有命中统计；默认不注入，手动可引用 |
| 看板即产品 | 看板降级为「任务」视图；首屏回答「现在该做什么」 |
| 状态说谎 | 等待/阻塞不能被显示成「执行中」；等待时长必须可见 |
| 拟人化过头 | 命名朴素（待你处理/晨间简报），人格留在文案语气里 |

## 7. 如果只做三件事（推荐）

| 顺位 | 做什么 | 为什么是它 | 成本 | 两周内可交付 |
|---|---|---|---|---|
| 1 | **今日工作台**：待你处理 + 今日焦点 + 今日完成（结果一句话）+ 一句话捕获 | 直接回答「我打开它干嘛」；用现有 `/state` 派生，几乎不动 Host | M | ✅ |
| 2 | **晨间简报**：08:30 推飞书 + 站内卡片 | 复用日报引擎与 Webhook，让插件在你不打开时也有价值；是「秘书感」的最短路径 | M | ✅ |
| 3 | **例行任务 + 模板**：每天/每周自动入队 + 5 个内置模板 | 从「我递任务」变成「它在等我」；最难被普通看板替代的差异化 | L | ⚠️ 先做每天/每周两档 |

如果只有两周：**先做 1 + 2，并把「优先级接入调度」顺手修掉**（成本 S、感知强）；第 3 件作为下一迭代的第一项。

**P0 之后最值得跟的一件事**：结果证据 + 待验收 + 👍/👎 沉淀闭环——它把用户已认可的「复盘/经验/技能」从档案变成能改进下一次任务的东西，是「越用越好用」的来源。
