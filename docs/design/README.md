# 任务管家 · 今日工作台（设计说明）

> 交付物：`docs/design/today-mockup.html`（单文件、零外部依赖，双击即可看）· 本文档为设计说明。

## 1. 设计目标

现行默认页是四列看板（待开始 / 排队中 / 处理中 / 已归档），它回答的是「系统里有什么」。升级后的首屏要回答用户自己的三个问题：

1. **今天做什么？** → 今日焦点（AI 排序 + 推荐理由 + 一键加入队列）
2. **什么需要我？** → 待我处理（审批 / 失败重试 / 技能候选，只留必须本人拍板的）
3. **进展如何？** → 进行中 + 今日完成（有进度、有一句话结果、有 👍/👎 反馈）

再加一条贯穿全局的**一句话快捷捕获**：不用分类、不用想放哪，先记下、稍后由秘书安排。

设计语气从「后台工具」改为「替我盯事的秘书」：文案用第一人称「我」对「你」说话（如「我在盯着」「到点我会来叫你」「不用你操心」），视觉上更安静——减少大色块 KPI、减少渐变面积、强化标题层级与留白，数字统一等宽/tabular。

## 2. 页面区块

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：品牌+在岗状态  今日/任务看板/复盘  主题·通知(3)·设置·头像 │
│ 问候区：日期 · 早安，朋友。 / 我在盯着（今日处理 4 件）        │
│ 快捷捕获：交代一件事…回车记下，稍后安排        [记下]          │
│ 秘书晨报：AI 一句话摘要 + 查看晨报 + 昨日完成 4 件             │
├───────────────────────────────┬──────────────────────────────┤
│ 待我处理  3 件                │ 今日小账                     │
│   审批 / 失败重试 / 技能候选   │   完成 4 · 进行中 2 · 待你 3 │
│ 今日焦点  3 件                │   本周省下 6.5h · tokens 128k│
│   01 继续昨天 02 截止今天 …    │ 例行任务（20:30 / 周五 17:00）│
│ 进行中  2 个（进度/耗时/模型） │ 快捷入口（看板/日报/复盘/经验）│
│ 今日完成  3 条（结果/👍👎/沉淀）│ 接下来的安排（18:00/21:00/22:00）│
├───────────────────────────────┴──────────────────────────────┤
│ 页脚：版本 · 设计稿说明 · ⌘K 命令面板 · 下次汇报 18:00          │
└──────────────────────────────────────────────────────────────┘
```

- **顶栏**：品牌（任务管家 + 秘书台在岗）、分段导航（今日选中，另两项静态可点）、右侧主题切换（CSS 变量 + JS 切 class，记忆到 localStorage）、通知红点 3、设置、头像。
- **快捷捕获**：整条输入即焦点环（focus-within）；回车/点「记下」有 toast 反馈；下方一句解释「不用想放到哪」，并提供示例 chip（点击回填输入框）。
- **秘书晨报**：顶部 2px 紫→蓝→薄荷渐变发丝线；一句 AI 摘要（关键时间/结论加粗）+「查看晨报」+ 昨日完成。
- **待我处理**：左上琥珀 / 玫红 / 紫状态轨；每条「类型标签 + 上下文 + 主操作 + 查看对话」；主操作按紧急度分级（审批=唯一紫色渐变按钮，其余为柔和色按钮）。含**空状态**（「今天没有需要你拍板的事」+ 上次清空时间 + 去看焦点）与**加载态**（骨架屏 + 「正在核对昨晚的结果…」）。
- **今日焦点**：编号 01/02/03；首卡高亮（渐变编号砖 + 紫色洗底）；每张含 AI 推荐标签 + 时效标签（继续昨天/截止今天/会议前）+ 一句推荐理由 + 加入队列（点击变「已加入队列」，进入演示态）。
- **进行中**：流式状态点 + 标题 + 预计完成时间；已运行 / 模型 / 思考强度 chips；6px 进度条 + 百分比；顶部「并发 2 / 4」。
- **今日完成**：一句话结果（用「」引用）+ 用时 + 目录/时间；👍/👎 互斥反馈（有一项预置「有用」态）；「沉淀为经验」虚线胶囊；底部「今天共完成 4 件 · 还有 1 件在『全部』里」。
- **今日小账**：3 个大数字（完成/进行中/待你处理，状态点语义一致）+ 本周省下 6.5 小时（7 日微型柱状图，今日高亮并标 2.1h）+ 今日 tokens 128k（输入/输出拆分）；页脚一句「周末我把这页账整理成周报」。
- **例行任务**：每天 20:30 检查依赖（8 小时后）、每周五 17:00 写周报（3 天后）；行悬停浮出箭头，整行可点。
- **快捷入口**：看板 / 日报 / 复盘 / 经验 2×2 磁贴，各带一行状态副标题。
- **接下来的安排**：18:00 收尾汇报、21:00 日报、22:00 复盘的时间线，配「到点来叫你」。
- **设计稿工具条**（左下，虚线框，仅 mockup）：常规 / 空状态 / 加载中三态切换；也可用 `?theme=dark&state=empty|loading` 直接打开对应状态。

## 3. 设计 token

**颜色**（明 / 暗双主题，均以 CSS 变量实现）
| Token | 明色 | 暗色 | 用途 |
| --- | --- | --- | --- |
| `--bg` | `#f1eff7` | `#0d0c14` | 页面底 + 顶部紫/蓝/暖杏环境光 |
| `--surface` / `-2` / `-3` | `#fff` / `#f8f7fc` / `#f0eef7` | `#16151f` / `#1c1b27` / `#242231` | 卡片 / 内嵌块 / 轨道 |
| `--line` / `-strong` / `-soft` | 黑 9% / 16% / 5.5% | 白 8.5% / 17% / 5.5% | 描边三档 |
| `--text` / `-2` / `-3` | `#1d1a2b` / `#5d5972` / `#767290` | `#f2f0fa` / `#b1adc3` / `#8d89a2` | 主 / 次 / 弱文字 |
| `--violet` / `--indigo` | `#8b5cf6` / `#6366f1` | 同 | 主色、进行中、主按钮渐变 |
| `--mint` / `--amber` / `--rose` / `--blue` | `#10b981` / `#f59e0b` / `#f43f5e` / `#3b82f6` | 同 | 完成 / 待处理 / 失败 / 会议·信息 |
| `--ink-*` | `#6d28d9` `#b45309` `#047857` `#be123c` `#1d4ed8` | 亮化版 | 状态色在浅底上的可读文字色（≥4.5:1） |
| `--tint-*` | 状态色 10–16% 混透明 | 16–19% | 标签/图标砖/进度底 |

状态语义固定：**待处理=琥珀、进行中=紫、完成=薄荷、失败=玫红、信息/会议=蓝**；主按钮渐变全页只给最高优先动作（记下 / 批准放量）。

**圆角**：`--radius-xl 24px`（侧栏卡片）· `--radius-lg 20px`（晨报/捕获/列表容器）· `--radius-md 16px`（小卡、onwatch）· 18px（待我处理/焦点卡）· `--radius-sm 13px`（按钮/输入）· 999px（胶囊）。**间距**：4 基数，常用 8/10/12/16/18/26/32；区块间距 30–34，卡片内边距 13–18。

**字号**（系统字体栈，中文 PingFang SC / 微软雅黑；标题可回落衬线 Songti SC）

| 层级 | 字号 / 行高 / 字重 |
| --- | --- |
| 问候标题 | 34 / 1.22 / 600（衬线，名字用紫色） |
| 区块标题 | 17 / 1.3 / 650 |
| 卡片标题 | 14.5 / 1.4 / 650 |
| 正文 | 12.5–13 / 1.6 |
| 辅助/元信息 | 10.5–11.5 / 1.4 |
| 大数字 | 27–34（`font-variant-numeric: tabular-nums`） |
**阴影**：卡片 `0 1px 2px rgba(24,18,48,.05), 0 22px 46px -30px rgba(60,35,120,.24)`；悬停加深并 `translateY(-2px)`；暗色改为内高光 + 深投影。
**布局**：`max-width 1240px`；桌面 `minmax(0,1fr) 372px / gap 26`（左约 2/3）；断点 1120（右栏 330）/ 980（单栏，侧栏卡片 2 列，首尾通栏）/ 860（顶栏换行、导航整行、CTA 换行）/ 640（全单栏）。
**动效**：140–220ms `cubic-bezier(.22,.61,.36,1)`；仅状态点脉冲、进度、骨架微光与悬停位移；`prefers-reduced-motion: reduce` 时全部动效降至 0.001ms。键盘 `:focus-visible` 统一 2.5px 紫色焦点环，偏移 2px。

## 4. 与旧看板的信息架构差异

| 维度 | 旧看板（现状） | 今日工作台（本稿） | 为什么 |
| --- | --- | --- | --- |
| 首屏问题 | 「任务分布在哪四列」 | 今天做什么 / 什么需要我 / 进展如何 | 用户抱怨「只是个看板」，首屏应先回答个人问题 |
| 主入口 | 四列看板 + 5 张粉彩 KPI 卡 | 问候 + 快捷捕获 + 晨报 + 需求收件箱 | 从「查看」变为「交代 + 处理」 |
| 信息优先级 | 按状态分列，人找任务 | 按「是否需要我」排序；只有 3 条待拍板 | 减少扫视成本，突出人工介入点 |
| 推荐能力 | 无 | 今日焦点：AI 排序 + 推荐理由 + 一键入队 | 秘书替你做计划，而不只是存任务 |
| 完成闭环 | 卡片状态徽章 | 一句话结果 + 用时 + 👍/👎 + 沉淀经验 | 形成「结果 → 反馈 → 经验」闭环 |
| KPI 表达 | 5 张大色块卡、渐变面积大 | 1 张安静的小账（数字 + 7 日微柱 + tokens） | 降低视觉噪音，保留价值感 |
| 导航 | 顶部按钮（日报/设置/发布） | 今日 / 任务看板 / 复盘 分段导航 + 通知 | 多视图雏形；看板降为二级页面 |
| 口吻 | 系统术语（阻塞/已暂停/领取） | 秘书第一人称（我在盯着/到点叫你） | 建立信任与陪伴感 |
| 新增模块 | — | 快捷捕获、晨报、待我处理、例行任务、今日小账、接下来的安排 | 支撑「主动性」与「掌控感」 |

旧看板保留为「任务看板」二级页面，写操作（发布、编辑、拖拽、设置等）仍复用现有抽屉/弹窗，不重做。

## 5. 留给插件实现的组件拆分建议

```
TodayPage                       ← 新视图，默认页；数据 GET /secretary/api/state
├─ PageHeader                   ← 品牌/日期/导航/主题/通知/头像（复用现有按钮与主题机制）
├─ Greeting                     ← 静态文案 + 今日问候
├─ QuickCapture                 ← 发布任务（复用 POST 发布接口，默认进「待开始」）
├─ MorningBrief                 ← AI 摘要（可先用日报/最新结果拼接，后续接独立生成）
├─ NeedsInbox                   ← 过滤 blocked/failed + 技能候选；行内审批/重试
│  ├─ NeedItem（tone: amber|rose|violet）+ EmptyState + Skeleton
├─ FocusList                    ← 推荐排序（截止/依赖/昨日未完成）；加入队列=promote
│  └─ FocusCard（AI 标签 + 理由 + CTA）
├─ RunningList                  ← status=running；进度用轮次/token 估算
├─ DoneList                     ← status=done 今日；反馈写回 feedback，点赞可转经验
└─ SideRail
   ├─ DailyLedger               ← counts + tokens + 省时聚合（新增 today 汇总字段）
   ├─ RoutineList               ← 例行任务（需新增数据模型，或先映射模板/定时）
   ├─ QuickLinks                ← 打开看板/日报/复盘/经验（复用现有抽屉）
   └─ UpcomingTimeline          ← 今日剩余固定节点（可选，P2）
```
**实现要点**：① 全部规则收敛到 `client.js` 现有 CSS 变量体系——`--surface`→`var(--dsw-alias-bg-layer-1)`、`--text`→`var(--dsw-alias-label-primary)`、`--text-2/3`→`label-secondary`、`--line`→`alias-border-l1`，状态色沿用旧 `--ps-violet/amber/mint/rose`；② 新增视图时保持单文件无构建（`tests/static-check.mjs` 有契约约束），组件按「区块函数 + 局部事件委托」拆，不引入框架；③ 演示稿里的 toast / 已加入队列 / 点赞态只是交互示意，真实实现需接 API 并给 loading/error 回滚；④ 侧栏窄宽度（真实侧栏约 360–600px）直接套用本稿 <900px 单栏布局，桌面稿是宽窗口/全页形态；⑤ 空状态、加载态、`prefers-reduced-motion` 与键盘焦点环在真实组件里必须保留。
**数据/API 增量建议**：`GET /state` 增加 `today` 聚合（todayDone / todayTokens / savedMinutes / needs / focus / routines / brief）；`POST /feedback`（任务结果有用/没用）；`POST /capture` 可先复用发布任务接口；「例行任务」与「焦点推荐」需要新增数据/逻辑，建议 P0 先做静态聚合与前端启发式，P1 再接 AI 生成。
**建议落地顺序**：P0 布局 + 待我处理 + 进行中 + 今日完成 + 快捷捕获（复用现有数据即可）→ P1 晨报摘要 + 焦点推荐 + 小账聚合 → P2 例行任务 + 时间线。
