> 本文件是 v0.6 的唯一权威规格（Lead 维护）。实现者只改自己负责的文件，其余文件由 Lead 收口。

> 背景：v0.5.0 现状审计见 `research/audit.md`、`research/ux-naming.md`、`docs/upgrade-blueprint.md`。
> **本会话不重启 Harness、不在真实 GUI 里重载插件**（重启会杀掉当前会话）。Host 逻辑用 Node 单测验证；浏览器半用静态契约检查验证；真机联调留给用户重载后。

## 0. 目标与范围

v0.6 只做「今日」这一件事：让打开插件的第一屏回答「今天做什么 / 什么需要我」，并让它在 08:30 主动发一份晨报。

**必须交付**

1. **今日工作台**：新默认视图（今日 / 任务 两个一级视图切换）。
2. **待你处理**：聚合阻塞/暂停/失败/技能候选；通知中心（铃铛 + 未读 + 最近动态）+ 头部数字。
3. **快捷捕获**：今日页一句话输入 → 自动创建「想法」任务（`status: idea`）。
4. **晨间简报**：Host 新模块（定时生成 + AI 提示词 + 本地兜底 + 文件 + Webhook 事件 + API + 设置区），今日页卡片 + 简报抽屉。
5. **优先级接入调度**：新入队任务按 紧急→高→普通→低 插入 pending 队列；拖拽 / 置顶仍是手动覆盖。
6. **数据 quick wins**：DSH 会话任务结果回填（`result/turns/usage/durationMs`）、前端接通 `GET /webhook/log`、修事实错误文案。
7. **命名第一轮**：见 §4.9（zh/en 同步）。
8. 测试（static-check / Host 单测 / api-check）与 README / locale / 版本号同步到 0.6.0。

**非目标（留到 v0.7）**：结果反馈👍👎、待验收、例行任务/模板、工作周报、成本预算、全局搜索/⌘K、卡片动作从 7 收敛到 2、项目/目标、全量检索、任务时间线。不要顺手做。

## 2. 数据与设置

### 2.1 `settings.morningBrief`（新增，加在 `settings.dailyReport` 之后）

```js
{
  enabled: true,                 // 默认开启
  time: '08:30',                 // HH:mm，24 小时制，默认 08:30
  dir: <stateDir>/briefs,        // 输出目录
  lastDate: null,                // 最近成功生成日期
  lastStatus: 'idle',            // idle|running|ok|failed
  lastError: null,
  lastGeneratedAt: null,
  generatingDate: null,          // 正在生成的日期（防重入）
}
```

- `STATE_VERSION` 保持 4（只加字段 + normalize 容错，参考 v9 evolution 的做法）。
- 用户 patch 只允许 `enabled/time/dir` 三个字段；`time` 非法 400「晨间简报时间必须是 24 小时制 HH:mm」；`dir` 非法 400「晨间简报目录不合法」；运行态字段由引擎写，不通过 settings patch。
- `store.js` 新增：`defaultMorningBrief(stateDir)`、`normalizeMorningBrief(raw, stateDir, previous)`、`TaskStore#updateMorningBrief(patch)`（只更新 lastDate/lastStatus/lastError/lastGeneratedAt/generatingDate）。
- `/state.settings` 自动带上 `morningBrief`（settings 全量返回）。
- `webhook.events` 新增 `morningBrief: true`（默认开启），`WEBHOOK_EVENTS` 变为 7 项（顺序：claimed/succeeded/blocked/failed/dailyReport/morningBrief/retrospective），`defaultWebhook()`、`normalizeWebhook` 同步。

### 2.2 任务字段（最小新增）

- `resultBackfillAt`（number，可选）：会话任务结果回填尝试时间，normalize 保留（数字才保留）。用于防止失败重试死循环。
- 不新增其它任务字段；不改状态机；不改 `STATE_VERSION`。

## 3. Host 行为

### 3.1 晨间简报模块 `host/briefs.js`

镜像 `host/reports.js` 的结构与写法（文件头注释、导出纯函数、`createBriefs({ctx, store, bridge, notify, options})` 返回 `{start, stop, kick, list, read, meta, today, generate, checkDue, recoverStale, isGenerating}`）。

**必须导出（供单测与 api 使用，名称精确）**：

- `isBriefDue(settings, now = Date.now())`：`enabled === true`、当前本地时间 ≥ `time`、`lastDate !== 今天`、`!generatingDate` → true。
- `buildMorningBriefPrompt({ date, yesterday, running, waiting, candidates, ideas, skills })`：纯函数，返回固定四段的严格提示词。
- `buildMorningBriefFallback({ date, yesterday, running, waiting, candidates, ideas, skills })`：纯函数，生成四段兜底 Markdown。
- `collectMorningBriefData(storeLike, now = Date.now(), date)`：从任务/技能数据整理 `{yesterday, running, waiting, candidates, ideas, skills}`（纯读；不要依赖文件系统）。
- `extractBriefBody(text, date)` / `normalizeMorningBriefText(text, date, data)`：复用 `reports.js` 的风格：强制标题 `# YYYY-MM-DD 晨间简报`、四个二级标题顺序不变；模型输出不合规时返回 `{content, fallback:true}`。
- `listBriefFiles(dir, limit = 200)` / `readBriefFile(dir, date)`：日期文件名 `YYYY-MM-DD.md`，列表按日期倒序。
- 常量：`BRIEF_TICK_MS = 30_000`、`BRIEF_POLL_MS = 1_000`、`BRIEF_MAX_WAIT_MS = 10 * 60 * 1000`、`BRIEF_DATE_PATTERN`。

**固定四段（标题文字与顺序不可变）**：

```
# YYYY-MM-DD 晨间简报

## 一、昨日回顾
## 二、今日焦点
## 三、等你处理
## 四、风险与提醒
```

- 先调模型（独立 AI 会话，cwd = 简报目录），约 1–3 分钟；失败 / 空 / 结构不合规 → 用 `buildMorningBriefFallback` 本地兜底，保证始终可读（与日报一致，兜底也算成功）。
- 数据口径：
  - **昨日回顾**：昨天结束（`endedAt` 在昨天）的队列任务（done/failed/cancelled），只写状态 + 一句话结果；DSH 会话任务只计数量。
  - **今日焦点**：至多 3 条。候选 = 当前 `pending`（按现有队列顺序）+ `idea` 里最新创建的；每条给「为什么是它」：`承接「上一任务」` / `优先级高` / `已在队列排队` / `想法待排期`。
  - **等你处理**：`blocked`（等你回复/审批）、`paused`、`failed`，至多 6 条；写明已等待时长（取 `updatedAt` 到 now）。
  - **风险与提醒**：等待 > 2 小时的 blocked / 运行 > 2 小时的 running / 待采纳技能候选数（从 `store.getEvolutionMeta()` 的 proposedSkillCount）/ 今天的定时节点（日报 21:00、复盘 22:00）。
- 模型提示词要求：简洁总结式，每项一行、≤40 字，不写 token/模型/路径等技术细节；不要输出代码块围栏。
- 生成成功：写文件（原子写：tmp + rename）→ `store.updateMorningBrief({lastDate,lastStatus:'ok',lastError:null,lastGeneratedAt:Date.now(),generatingDate:null})` → `notify('morningBrief', {date, content, path})`。
- 生成失败：`lastStatus:'failed'`、`lastError` 记录、`generatingDate:null`（不写文件）。
- 定时：`start()` 每 30s `checkDue()`；`recoverStale()` 在 start 时把上次 running/generatingDate 置为 failed；`kick()` 在设置更新后立即检查；与日报相同的 `unref()` 处理。
- 防重入：`generate()` 在 `generatingDate` 非空时抛 `HttpError(409, '晨间简报正在生成中')`。
- 文件默认目录 `<stateDir>/briefs`；`stateDir` 用现有 `resolveDataDir()`。

### 3.2 API（`host/api.js`，前缀 `/secretary/api`）

`GET /briefs` →

```json
{ "ok": true, "briefs": [{"date":"2026-11-11","path":"...","bytes":512,"updatedAt":1794...}],
  "settings": { "enabled": true, "time": "08:30", "dir": "...", "lastDate": "...", "lastStatus": "ok",
                "lastError": null, "lastGeneratedAt": 179..., "generatingDate": null } }
```

`GET /briefs/content?date=YYYY-MM-DD` → `{ok:true,date,path,content}`；日期非法 400「日期格式应为 YYYY-MM-DD」；不存在 404「该日期没有晨间简报」。

`POST /briefs/generate` `{date?}` → `{ok:true,date}`（后台生成，客户端轮询 `/state` / `/briefs`；与日报生成同一模式）。

- `/state` 新增 `briefs: briefs.meta()`（形状与 `reports` 一致）。
- `settings` 处理器：`body.morningBrief` 必须是对象（数组/null 之外的 400「晨间简报设置格式不正确」）；更新后 `briefs.kick()`。
- `operations` 增加 `listBriefs / briefContent / generateBrief`（供工具/测试复用）。
- 路由注册在 `handle` 的 GET/POST 分支，与现有风格一致；不要另起裸路由。

### 3.3 优先级接入调度（`host/store.js` + 极少量 `host/api.js`）

- 新增导出纯函数 `pendingInsertIndex(tasks, task)`（返回应插入的数组下标），规则：
  1. 只看 `status === 'pending'` 的任务段（保持相对顺序）；
  2. 优先级 rank：urgent=0 / high=1 / normal=2 / low=3；
  3. 插到「第一个 rank 大于新任务 rank 的 pending 任务」之前；没有则插到最后一个 pending 之后；没有 pending 时插到数组末尾。
- 应用位置：
  - `TaskStore#add`：`status === 'pending'` 时按上式插入（idea 仍 append）。
  - `TaskStore#addBatch`：逐个按上式插入 pending。
  - `TaskStore#promote`（idea→pending）：不再「保持原位」，改为按上式重新插入。
  - `TaskStore#update` 的调用方 `api.updateTask`：pending 任务改 priority 后调用 `store.repositionPending(id)`（新增方法）重新插入。
  - `api.action` 的 `retry`：pending 后调用 `store.repositionPending(id)`。
  - `moveToPendingFront`（置顶/run-next）与 `reorder`（拖拽）保持现有行为，作为手动覆盖，不强制重排。
- `scheduler.claimPending` 不用改排序逻辑（仍然按数组顺序领取），但必须保证「pending 数组顺序 = 入队排序结果」。导出纯函数 `pendingInClaimOrder(tasks)`（filter pending 后原样返回，或排序后的视图）供单测断言。
- 文档口径：优先级从「仅展示」改为「参与入队排序」；`host/tool.js` 的工具描述、参数说明、README、locale 文案同步改。

### 3.4 DSH 会话任务结果回填（`host/scheduler.js`）

- 现有会话任务（`source === 'session'`）在 running→done 时**没有** `result`。修复：
  - 状态迁移 running→done 后调用 `backfillSessionResult(task.id)`：`bridge.summarize(sessionId)` → 写入 `result = {finalAnswer,turns,durationMs,usage}`（字段形状与 queue 任务一致），并写 `resultBackfillAt = Date.now()`。
  - 已存在的、`status === 'done' && !result && sessionId && !resultBackfillAt` 的会话任务，由 tick 有界回填：每次 synchronize 最多处理 **5 个**，一个失败写 `resultBackfillAt`（不无限重试）。
  - 不阻塞领取/结算：回填在 sync 后异步串行进行；异常只 log。
  - 不修改 `finalizeResult` 对 queue 任务的现有语义。
- 会话任务回填出的 `result.durationMs` 允许为 `undefined`（会话没有可靠的起止），不要伪造。

### 4.2 今日页区块（自上而下）

1. **问候行**：日期（本地 `M月D日 · 周X`）+「早安，今天也交给我。你只需要决定，先做哪一件。」+ 右侧「我在盯着」小卡（今日已处理 N 件 / 待你处理 M 件）。
2. **快捷捕获**：一行输入（placeholder「交代一件事…回车记下，稍后安排」）+「记下」主按钮；回车或点按钮创建 `{title: 输入, prompt: 输入, cwd: 最近使用目录 || 默认工作目录, status:'idea', priority:'normal'}`；成功 toast「已记下，稍后在「想法」里安排」；清空输入并刷新快照；失败 toast 错误。输入为空不提交。
   - 默认目录来源：客户端现有 `guessDefaultDirectory(ctx)` + 最近一次工作目录（若已有即可）；发送前必须保证是绝对路径。
3. **晨间简报卡**：数据取 `/state.briefs`。
   - 有今日简报：日期 + 前 2 行摘要（或「晨报已生成」）+「查看晨报」；
   - 今日未生成：「今天还没有晨报」+「立即生成」（POST `/briefs/generate`）+ 下次自动生成时间；
   - settings.morningBrief.enabled=false： 「晨间简报已关闭」+「去设置」；
   - generatingDate 非空：「正在生成晨报…」；
   - 点「查看晨报」打开**简报抽屉**（参考 ReportsDrawer，宽度 `min(720px,100%)`，日期列表 + Markdown 原文 + 刷新，复用现有 Markdown 渲染方式）。
4. **待你处理**（P0）：从快照派生：
   - `blocked` → 类型「等你回复」，副文案「等待你的回答或审批 · 已等 X」；主操作「打开会话」；次操作「暂停」；
   - `paused` → 「已暂停」+「继续」/「打开会话」；
   - `failed` → 「失败待重试」+「重试」/「打开会话」；
   - `evolution.proposedSkillCount > 0` → 「N 个技能候选待采纳」+「查看候选」（打开复盘抽屉的「技能」tab）；
   - 空状态：「今天没有需要你拍板的事，剩下的我盯着。」
   - 每条点击可打开任务详情抽屉；`blocked` 的打开会话直接进详情抽屉并聚焦输入框（复用现有 chat 输入）。
5. **今日焦点**：候选 = `pending`（按队列顺序）+ 若不足 3 条，补最新 `idea`；展示最多 3 条；`换一批` 在候选 >3 时循环后移 3 位；每条：标题 + 理由（承接上一任务 / 高优先级 / 已在队列 / 想法待排期）+ 主操作（pending→「立即执行」action run；idea→「加入队列」action promote）+「编辑」。
   - 空状态：「还没有可排的事。用上面输入框记一件，或去任务看板发布。」
6. **进行中**：`running` 任务行（标题、已运行 X、模型/思考强度、打开会话、暂停）；`paused/blocked` 不在此区（已在待你处理）；空状态：「目前没有正在跑的任务。队列会按顺序自动执行。」
7. **今日完成**：今天 `endedAt` 的 done 任务，最多 5 条：时间 + 标题 + 一句话结果（`result.finalAnswer` 首句，截断 80 字）+ 用时；操作「查看」；底部「今天共完成 N 件 · 查看全部」→ 切到任务视图。空状态：「今天还没有完成的任务。」
8. **右栏**（窄屏折到主栏下方）：
   - **今日小账**：今日完成数、进行中数、待你处理数、今日 tokens（当天 ended 任务 `result.usage` 的 input+output 之和，展示为 `96k` 这种紧凑格式；没有数据时显示「—」）；再补一行「本周完成 N 件」（可选）。
   - **快捷入口**：任务看板 / 日报 / 复盘 / 经验 四个按钮（打开对应视图/抽屉）。
   - **通知卡**：`settings.webhook.enabled` 状态 + 最近一次发送（`webhook.lastStatus/lastAt/lastEvent`）+「查看通知记录」（打开通知记录弹窗：`GET /webhook/log` 列表：事件、时间、成功/失败、错误；空状态「还没有投递记录」）。

### 4.3 通知中心

- 头部铃铛按钮：未读数 = 派生事件中 `updatedAt > lastSeenAt` 的数量（`localStorage` 键 `dsh-ps-last-seen`，毫秒时间戳；没有则默认 0 未读）。未读 > 0 时红点显示数字（>9 显示 9+）。
- 点击打开 popover（`role="dialog"` + `aria-label`）：
  - 「待你处理」条目（同 §4.2-4，最多 4 条）；
  - 「最近动态」：快照中任务按 `updatedAt` 倒序，取最近 24h 的 done/failed/blocked，最多 6 条，显示状态 + 标题 + 相对时间，点击打开任务抽屉；
  - 底部「全部标记已读」；打开 popover 不自动已读。
- 无新动态时空状态「暂时没有新动态」。

### 4.4 设置弹窗

## 7. 已知边界（写入 README）

- 晨间简报与日报一样运行在 Host 进程内：Harness 关闭时不生成，重开后按 due 规则补跑（只补当天，不补历史）。

- 会话任务的结果回填依赖 DSH session 日志仍可读；会话被删除后无法回填。
- 优先级参与的是**入队插入排序**；用户拖拽/置顶仍是更高优先的手动覆盖。
- v0.6 通知中心是 `/state` 派生的「最近动态」，不是持久事件流（时间线/持久事件在 v0.7）。
- 5 张 KPI 卡、列内搜索、卡片 7 图标等视觉降噪项顺延 v0.7（v0.6 先交付 IA 与主动节奏）。
